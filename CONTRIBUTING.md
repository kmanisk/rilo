# Contributing

Contributions are welcome. Prefer focused pull requests that are straightforward to test and review.

## Workflow

1. Branch from `main`.
2. Follow the setup instructions in `README.md` and confirm the current build or application works.
3. Keep each pull request to one logical change.
4. Run the repository's relevant formatting, linting, build, and test commands.
5. Document what changed, why, and how it was verified.

For user-facing changes, include screenshots or terminal output when they make the change easier to review. Do not commit secrets, generated build output, local caches, or editor-specific files.
